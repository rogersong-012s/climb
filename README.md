# 登峰灶急

《登峰灶急》（Stair Sprint · Taipei 101）是以節奏操作、第一人稱樓梯場景與怪物戰鬥為核心的瀏覽器遊戲。玩家從 1F 自動攀登至 101F，踩準節奏球提升速度，沿途收集新節奏、處理怪物事件並挑戰戰鬥。

本文件記錄目前版本的主要玩法與規則。遊戲以原生 HTML、CSS 與 JavaScript ES Modules 製作，可作為靜態網站部署。

## 開始遊戲與操作

- **電腦踩拍／戰鬥操作：**按 `Space`。
- **手機：**點擊遊戲場景或操作區；QTE 字母請直接點選字母卡。
- **暫停／繼續：**按 `Esc` 或畫面上的暫停按鈕。
- **防禦回合：**只在中央盾牌亮起的判定窗口按 `Space` 或點擊場景；提前輸入會被忽略。
- **強化選擇：**怪物戰鬥勝利後，點選兩張候選強化卡之一。

開始畫面與暫停選單都能切換防暈模式。OFF 使用第一人稱轉身，ON 使用簡易轉場；設定會保存在目前瀏覽器的 `localStorage`。

## 自動攀登與速度

玩家開始遊戲後會自動向上攀登，樓層進度由實際速度與經過時間連續計算，不需要靠 HIT 才移動。

- 初始速度與最低速度：`0.10 F/s`。
- 初始速度上限：`0.30 F/s`。
- 每秒自然減速：`0.005 F/s²`，速度不低於最低值。
- 一顆節奏球的所有拍點都成功時，基礎速度增加 `0.02 F/s`，COMBO 增加 1。
- 完美節奏另觸發 `+0.10 F/s`、持續 `0.4` 秒的短暫衝刺；衝刺可暫時超過速度上限，不會永久提高基礎速度。
- 怪物擊敗或成功使用跳怪技能時，速度增加 `0.01 F/s`，速度上限增加 `0.015 F/s`。
- 攀登至 `.0` 或 `.5` 平台時會停下轉身；轉身前停頓與轉身時間依當下速度等比例調整。轉身期間攀登與自然減速暫停，節奏球仍持續運作。

遊戲暫停或進入怪物事件、戰鬥等停止攀登的階段時，樓層進度與自然減速不會繼續累積。

## 節奏球

節奏球從左向右單向移動。每輪先在左側準備兩拍，再開始移動；正常拍速下，實際一拍約 `384.6 ms`，因此準備時間約 `769 ms`。球依照拍點資料顯示黃色判定區，玩家需在目前拍點的判定窗口按鍵。移動速度倍率為 `1.3`；痠痛狀態會降低拍速。拍點、球位置與判定共用同一份時間進度。

| 球色 | 每輪拍數 | 必須命中的拍點 | 技能充能基礎能量 | 解鎖樓層 |
| --- | ---: | --- | ---: | ---: |
| 紅 | 5 | 2、3、4 | 1 | 開始可用 |
| 藍 | 5 | 1、3 | 1 | 開始可用 |
| 黃 | 6 | 2.5、3.5、5、5.5 | 3 | 16F 光球 |
| 綠 | 6 | 1、2.5、3、4、4.5 | 6 | 36F 光球 |
| 紫 | 8 | 1.5、2、3.5、4、4.5、6、6.5、7 | 10 | 61F 光球 |

已解鎖的球種以等權重抽選。表中的拍數就是球從開始移動到軌道最右端的行程拍數；正常拍速下，5 拍球約 `1.92` 秒、6 拍球約 `2.31` 秒、紫球 8 拍約 `3.08` 秒。準備時間另計；抵達右端後空軌道等待 `0.1` 秒，再生成下一顆球。

每輪按鍵額度等於該球的 HIT 目標數；用完後不再接受額外輸入。正常攀登時，每個拍點成功會立即提供跳怪技能能量；單格成功不會直接增加攀登速度或 COMBO。只有整顆球全部命中，才會結算完美節奏獎勵。正常攀登中錯按或漏拍會使本輪無法完美並將 COMBO 歸零；即使已判定 HIT 或 MISS，球仍會跑到右端才結束本輪。戰鬥攻擊也使用節奏球，但不會累積跳怪技能能量或觸發一般攀登的速度衝刺。

### 判定區與 COMBO

- 基礎判定寬度由 `0.30` 起，每 COMBO 減少 `0.01`，最低為 `0.18`。
- 疲勞會額外減少 `0.04`，疲勞狀態下最低寬度為 `0.14`。
- 每張節奏精準強化卡增加相當於基礎寬度 `10%` 的判定寬度。
- 判定窗口會依相鄰拍點距離再限制，避免相鄰窗口重疊。
- 完美球使 COMBO 加 1；未完美的球會歸零。技能充能的 COMBO 加成取該次 HIT 當下的 COMBO，最高按 12 計算。

### 跳怪技能充能

每次正常攀登的單格 HIT 依「球種總能量 ÷ 該球 HIT 目標數」取得能量，再乘上 `1 + min(COMBO, 12) × 1%`。部分命中仍可依成功格數充能；戰鬥節奏不充能。

- 每 `48` 能量取得 1 次技能，最多儲存 `3` 次。
- 技能在接近下一隻尚未處理的怪物時開放，距離約為目前攀登速度的 2 秒路程。
- 使用技能會跳過該怪物事件並取得速度成長，不跳過樓層距離，也不取得怪物戰鬥的強化卡。

## 怪物事件與 DEBUFF

每次新遊戲會在每個五層區間預先隨機安排一個怪物事件，共 20 個；觸發位置在樓梯途中的 `.2` 或 `.7`，以樓層跨越方式精確觸發。怪物在首次遭遇時抽選，事件會保留同一隻怪物與出生位置。

遭遇流程為警告閃紅、怪物入場、施法命中、顯示 DEBUFF、答案預告，再進入字母 QTE。一般遭遇 QTE 的作答時間為 `4` 秒；錯誤的字母順序會清空目前輸入，可在時間內重試。玩家完成任一組解法都算成功並進入戰鬥：

- 解法為 `CURE` 時，若對應 DEBUFF 存在就解除。
- 其他解法依怪物資料完成效果，但不會因此解除已中的 DEBUFF；成功仍會進入戰鬥。
- 時間到仍未完成解法時，玩家退回 `3F`，保留樓層小數；同一事件恢復待觸發，重新向上跨過原位置時會再次遇到同一隻怪物。

| 怪物 | 解除狀態的答案 | 另一組答案 |
| --- | --- | --- |
| 肌肉怪 | `DRUG`：解除痠痛 | `PAN`：以平底鍋攻擊，帶著痠痛進入戰鬥 |
| 眼睛怪 | `EYE`：解除視野模糊 | `PAN`：攻擊怪物，保留視野模糊進入戰鬥 |
| 疲勞怪 | `REST`：解除疲勞 | `COFFEE`：帶著疲勞進入戰鬥 |

目前的 DEBUFF：

| 狀態 | 效果 |
| --- | --- |
| 痠痛 | 節奏球拍速倍率降為 `0.72`。 |
| 視野模糊 | 節奏軌道模糊 `1.3px`。 |
| 疲勞 | 判定區額外縮小 `0.04`。 |

DEBUFF 會依玩家實際攀登距離扣除剩餘樓層；同類狀態再次套用會提高嚴重度（最多 3 級）並重新計時，不同狀態可以同時存在。

## 怪物戰鬥

QTE 成功後進入戰鬥。怪物最大 HP 依事件順序成長：第 1 隻 `100 HP`，之後每隻增加 `5 HP`。

### 攻擊回合

玩家完成一顆攻擊節奏球後：

- 全部拍點命中：進入快速連打，傷害為基礎攻擊力加上連打次數乘以每次連打傷害。
- 部分命中：依成功拍點比例造成基礎攻擊傷害，不進入有效連打。
- 初始基礎攻擊力為 `20`；成功連打的基礎傷害為每次 `2`。強化卡可增加基礎攻擊、連打傷害或判定範圍。

### 防禦回合

防禦回合隨機抽紅盾或藍盾。漩渦提示後，雷射依時間軸射向中央盾牌；命中前 `0.3` 秒盾牌開啟判定窗口。紅盾有 2 發，間隔為 `0.6` 秒；藍盾有 3 發，間隔為 `0.8、0.6、0.8` 秒。每發須分別防禦，整輪所有攻擊完成後才結算。

- 成功輸入會在雷射抵達時格擋。
- 漏防後會進入 `4` 秒緊急 QTE；成功可避免新增 DEBUFF，失敗會套用怪物的負面狀態，戰鬥繼續。
- 防禦階段沒有玩家 HP 扣除規則。

擊敗怪物後，攀登速度與速度上限成長，並從三種強化卡中隨機提供兩張選一張：基礎攻擊、連打攻擊、節奏精準。跳怪技能不提供這組卡牌。

## 結算、設定與開發

抵達 101F 即完成本局。最佳通關時間與防暈模式設定保存在目前瀏覽器的 `localStorage`；不同瀏覽器與無痕視窗各自保存。

本機開發需要 Node.js 18 或更新版本：

```sh
npm start
```

預設網址為 `http://127.0.0.1:8001/`。遊戲以 ES Modules 載入，請透過 HTTP 開啟，不要直接使用 `file://`。

```sh
npm test
```

測試使用 Node.js 內建的 `node:test`，不需安裝額外套件。

開發用自動遊玩可用 `?debug=1` 啟用，並可用 `&rate=0.8` 設定整顆節奏球的完美率；例如 `http://127.0.0.1:8001/?debug=1&rate=0.8`。DEBUG 會自動開始遊戲，加入 `&autostart=0` 可停用自動開始。

主要規則與平衡數值集中於 `js/config.js`；遊戲可部署到 GitHub Pages 等靜態網站服務。
